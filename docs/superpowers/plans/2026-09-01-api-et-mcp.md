# API REST + MCP Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Exposer une API REST Bearer sur le `httpRouter` Convex déjà là (`*.convex.site`), avec jeton montré une fois et hashé, plus un serveur MCP stdio qui rejoue les mêmes routes — sans second routeur HTTP, sans upload média, sans POST public de leads.

**Architecture:** Les routes `/api/v1/*` s'enregistrent sur `packages/backend/convex/http.ts` à côté de Better Auth. Le Bearer est un jeton de site (owner-équivalent) : généré par owner/admin, stocké uniquement en SHA-256 dans `apiTokens`, jamais dans `settings`. Les `httpAction` vérifient le hash puis appellent des `internalQuery`/`internalMutation`. Le webhook Make (HMAC sortant `x-astrotan-signature`) ne bouge pas. Le MCP stdio (`@astrotan/mcp`) n'est qu'un client des mêmes URLs.

**Tech Stack:** Convex `httpRouter` / `httpAction`, Web Crypto (`lib/token.ts`), TanStack Start, `@modelcontextprotocol/sdk` stdio. Skills `@.claude/skills/convex-function`, `@superpowers/test-driven-development`.

`http.ts` après `authComponent.registerRoutes` :

```ts

```

`registerSiteApi` pose, **sur ce même `http`**, un `httpAction` par méthode (`GET` `POST` `PATCH` `DELETE` `OPTIONS`) en `pathPrefix: "/api/v1/"`.

Flux du handler :

1. OPTIONS → 204 + CORS
2. openapi / docs → sans Bearer
3. sinon `extractBearer` ; absent → 401
4. `hashToken` + lookup `internal.siteApi.lookupToken` ; mismatch → 401
5. `parseApiRoute` ; null → 404
6. `ctx.runQuery` / `runMutation` ; `ConvexError` → `statusForCode`
