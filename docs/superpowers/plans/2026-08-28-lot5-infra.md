# Lot 5 — Infra : Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `git push` sur `main` déploie l'ensemble — functions Convex, site Astro, dashboard TanStack Start — derrière Traefik sur le VPS, en HTTPS, avec une procédure de rollback qui rejoue le pipeline entier sur un sha antérieur.

**Architecture:** Deux images Docker multi-stage construites depuis la racine du monorepo (`node:22-alpine`, corepack + pnpm, runtime non-root taillé par `pnpm deploy --legacy --prod`). Traefik v3 termine TLS et route par `Host()`. La CI déploie Convex **avant** de construire les images, parce que le build d'Astro interroge le déploiement. Le rollback rejoue le pipeline complet, jamais les images seules.

**Tech Stack:** Docker · BuildKit · Traefik v3 · GitHub Actions · GHCR · pnpm 10.34.5 · Node 22 · srvx 0.12.7

**Spec:** `docs/superpowers/specs/2026-08-27-astrotan-design.md` (sections 7 et 9)

## Global Constraints

- **Versions exactes, jamais élargies** : `astro@7.2.8`, `@astrojs/node@11.1.4`, `@tanstack/react-start@1.168.49`, `convex@1.45.0`, `better-auth@1.6.17`, `@convex-dev/better-auth@0.12.5`, `react@19.2.8`, `tailwindcss@4.3.3`, `srvx@0.12.7`. Ce lot n'en monte aucune.
- **Node 22, pnpm 10.34.5.** `packageManager` de la racine fait foi ; les images l'activent par corepack, elles ne réinstallent pas pnpm à la main.
- **Copier des workspaces entiers dans l'image, jamais des chemins fichier par fichier.** L'arbre bouge (fichiers supprimés, `marked` ajouté à `apps/web` récemment) ; un `COPY apps/web/package.json …` énuméré casse à la prochaine tâche. La sélection se fait par `.dockerignore`, pas par une liste de `COPY`.
- **Le lockfile fait foi.** `pnpm install --frozen-lockfile` dans l'image. Toute tâche qui touche une `package.json` régénère `pnpm-lock.yaml` et le commite dans la même tâche.
- **`convex deploy` précède le build des images.** Le build d'Astro prérend `src/pages/index.astro`, qui interroge Convex : sans schéma déployé, l'image ne se construit pas (spec §7).
- **Un rollback d'image ne rollback pas Convex.** Toute procédure de retour arrière rejoue le pipeline complet sur le sha visé (spec §7, « Rollback et migrations »).
- **Un seul réplica de `web`.** `memoryCache()` est par processus : une invalidation ne touche que l'instance qui a reçu le POST (`apps/web/src/pages/api/revalidate.ts`, dernier commentaire du fichier). `deploy.scale` reste à 1 tant qu'un provider de cache partagé n'existe pas.
- **Aucun secret dans une image ni dans un `ARG`.** `PREVIEW_SECRET` et `REVALIDATE_SECRET` sont fournis à l'exécution par l'environnement du conteneur. Seules des valeurs publiques (`PUBLIC_CONVEX_URL`, `VITE_*`) passent en build-arg — Vite/Astro les fige dans le bundle, ce qui est exactement pourquoi un secret ne doit jamais y passer.
- **Port 3000 occupé sur la machine de dev.** Dans les conteneurs : `web` écoute 4321, `admin` écoute 3000 ; côté hôte, le compose de smoke-test publie 4321 et 3001.
- TDD au sens de ce lot : **exécuter la commande qui échoue avant d'écrire le correctif**, coller la sortie réelle dans le rapport. Conventional Commits en anglais, échanges en français.

## L'invariant du lot

> **Le pipeline est reproductible et réversible : n'importe quel sha de `main` se redéploie intégralement — functions Convex comprises — par une seule commande, et aucun conteneur ne détient de secret figé au build.**

Un déploiement qui « marche une fois » ne vaut rien ici. Juger chaque tâche contre cette propriété : est-ce que rejouer cette étape sur un sha antérieur reproduit exactement le même état ?

```ts
// apps/web/src/pages/api/_tests/health.test.ts
import { describe, expect, test } from "vitest"
import type { APIContext } from "astro"
import { GET } from "../health"

// Un faux contexte minimal : `cache.set` est la seule chose que la route
// touche. On l'observe pour vérifier l'opt-out de cache, exactement comme
// `revalidate.test.ts` le fait pour son propre `context.cache.set(false)`.
function makeContext() {
  const calls: Array<boolean> = []
  const context = {
    cache: { set: (value: boolean) => calls.push(value) },
  } as unknown as APIContext
  return { context, calls }
}

describe("GET /api/health", () => {
  test("répond 200 sans toucher Convex", async () => {
    const { context } = makeContext()
    const response = await GET(context)
    expect(response.status).toBe(200)
    expect(await response.text()).toBe("ok")
  })

  test("n'est jamais mise en cache", async () => {
    const { context, calls } = makeContext()
    await GET(context)
    expect(calls).toEqual([false])
  })
})
```

```ts
// Cible du `healthcheck` Docker du service `web` (docker/docker-compose.yml).
// Délibérément sans aucune dépendance : pas d'appel Convex, pas de lecture
// d'env, pas de secret comparé. Un healthcheck qui interroge Convex

export const prerender = false

  context.cache.set(false)
  return new Response("ok", {
    status: 200,
    headers: { "content-type": "text/plain; charset=utf-8" },
  })
}
```

### Task 3: Wrapper srvx du dashboard

- [x] **Step 1: Ajouter la dépendance**

- [x] **Step 2: Écrire le wrapper**

```js
// apps/admin/serve.mjs
// Livrable du lot 5, spec §9 (réponse Q2 du spike d'intégration).
//
// `vite build` (TanStack Start) produit `dist/server/server.js`, qui n'est
// PAS un serveur : il exporte `default = { fetch }`, un handler au format
// Web Fetch. `node dist/server/server.js` charge le module, n'ouvre aucun
// socket, et le processus sort — ce qui, dans un conteneur, ressemble
// exactement à un crash au démarrage. Ce fichier est le seul point qui
// transforme ce handler en processus qui écoute.
//
// Le chemin d'import est relatif à ce fichier : l'image de production copie
// `serve.mjs` et `dist/` côte à côte sous `/app` (docker/admin.Dockerfile),
// la même disposition que le dépôt.
import { serve } from "srvx"
import handler from "./dist/server/server.js"

// `hostname: "0.0.0.0"` et non le défaut : dans un conteneur, écouter sur
// la loopback rend le service injoignable depuis Traefik comme depuis le
// healthcheck, sans le moindre message d'erreur.
serve({
  fetch: handler.fetch,
  port: Number(process.env.PORT ?? 3000),
  hostname: "0.0.0.0",
})
```


```
# `COPY . .` : ce fichier est ce qui décide du contenu de l'image, et il
# raisonne par catégorie — jamais par chemin applicatif nommé. L'arbre du
# dépôt bouge à chaque lot ; une liste de `COPY` explicites casserait, ce
# filtre non.
.git

**/node_modules
dist
**/dist
.output
**/.output
.astro
**/.astro
.turbo
**/.turbo
.claude
docs
# Tout `.env*` sauf les exemples : aucun secret local ne doit pouvoir
# entrer dans une couche d'image, même en étant écrasé plus tard — les
# couches restent lisibles.
**/.env
**/.env.*
!**/.env.example
**/.DS_Store
**/*.tsbuildinfo
```

- [x] **Step 2: Écrire le Dockerfile**

```dockerfile
# syntax=docker/dockerfile:1.7
# Image du site public (spec §7). Contexte de build : la RACINE du dépôt
# (`docker compose` le fait avec `context: ..`), pas `apps/web` — c'est un
# monorepo pnpm, et le lockfile qui fait foi vit à la racine.
FROM node:22-alpine AS base
ENV PNPM_HOME="/pnpm" \
    PATH="/pnpm:$PATH" \
    COREPACK_ENABLE_DOWNLOAD_PROMPT=0
# corepack active la version de pnpm épinglée par le `packageManager` de la
# racine. Ne jamais `npm i -g pnpm` ici : ce serait une seconde source de
# vérité pour la version du gestionnaire de paquets.
RUN corepack enable
WORKDIR /repo

FROM base AS build
# L'arbre entier, filtré par `.dockerignore`. Un `COPY package.json`
# préalable améliorerait le cache de couche, mais énumérer les manifestes
# d'un monorepo dont les packages bougent est précisément la liste qui
# casse ; le lockfile suffit à rendre l'installation déterministe.
COPY . .
RUN pnpm install --frozen-lockfile

# Publique, jamais secrète : Vite/Astro fige cette valeur dans le bundle
# (`import.meta.env.PUBLIC_CONVEX_URL`, apps/web/src/lib/convexClient.ts),
# y compris dans la sortie SSR. Conséquence à connaître : changer d'URL de
# déploiement Convex impose de reconstruire l'image, pas de redémarrer le
# conteneur. Le déploiement visé doit être joignable PENDANT ce build —
# `src/pages/index.astro` est prérendu et interroge Convex (spec §7, et
# c'est pourquoi `convex deploy` précède le build des images en CI).
ARG PUBLIC_CONVEX_URL
ENV PUBLIC_CONVEX_URL=$PUBLIC_CONVEX_URL
RUN test -n "$PUBLIC_CONVEX_URL" || (echo "PUBLIC_CONVEX_URL build-arg is required" && exit 1)
RUN pnpm --filter @astrotan/web build

# `pnpm deploy` reconstruit un arbre autonome avec les seules dépendances
# de production de ce package. `--legacy` est obligatoire depuis pnpm 10 :
# sans lui la commande refuse de tourner sur un workspace qui n'a pas
# `inject-workspace-packages=true` (ERR_PNPM_DEPLOY_NONINJECTED_WORKSPACE),
# et ce dépôt ne l'active pas — ce réglage change le mode d'installation de
# tout le monorepo pour un besoin qui n'existe qu'ici.
RUN pnpm deploy --legacy --filter @astrotan/web --prod /out
# `deploy` copie les sources du package, pas ses artefacts de build
# (`dist/` est ignoré) : le résultat du build se copie explicitement.
RUN cp -r apps/web/dist /out/dist

FROM base AS runtime
ENV NODE_ENV=production \
    HOST=0.0.0.0 \
    PORT=4321
WORKDIR /app
# `node` est l'utilisateur non-root fourni par l'image officielle (uid 1000).
COPY --from=build --chown=node:node /out ./
USER node
EXPOSE 4321
# Le mode standalone de @astrojs/node sert les pages prérendues ET exécute
# les routes on-demand depuis ce même processus (spec §6.1).
CMD ["node", "./dist/server/entry.mjs"]
```

```dockerfile
# syntax=docker/dockerfile:1.7
# Image du dashboard (spec §7). Même socle et mêmes règles que
# docker/web.Dockerfile — lire ses commentaires pour corepack, le `COPY .`
# et `pnpm deploy --legacy`.
FROM node:22-alpine AS base
ENV PNPM_HOME="/pnpm" \
    PATH="/pnpm:$PATH" \
    COREPACK_ENABLE_DOWNLOAD_PROMPT=0
RUN corepack enable
WORKDIR /repo

FROM base AS build
COPY . .
RUN pnpm install --frozen-lockfile

# Trois valeurs publiques, figées dans le bundle client par Vite. Aucune
# n'est un secret : URL du déploiement Convex, URL de son site HTTP, et
# origine publique du site Astro (le bouton « Prévisualiser » y ajoute

ARG VITE_CONVEX_URL

ARG VITE_WEB_SITE_URL

    VITE_CONVEX_SITE_URL=$VITE_CONVEX_SITE_URL \
```

- [ ] **Step 1: Écrire le workflow**

```yaml
# .github/workflows/deploy.yml
name: Deploy

on:
  push:
    branches: [main]
  # Permet de rejouer un déploiement sans commit vide.
  workflow_dispatch:

# Un déploiement à la fois, et jamais annulé en cours de route : une image
# poussée puis abandonnée entre `convex deploy` et le `compose up` laisse
# le backend en avance sur les conteneurs.
concurrency:
  group: deploy
  cancel-in-progress: false

jobs:
  deploy:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: "22"

      - name: Enable Corepack
        run: corepack enable

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      # ÉTAPE 1 DU PIPELINE (spec §7) — obligatoirement avant le build des
      # images : `apps/web` prérend `src/pages/index.astro`, qui interroge
      # Convex. Construire l'image d'abord ferait lire au build un schéma
      # qui n'existe pas encore.
      - name: Deploy Convex functions
        env:
          CONVEX_DEPLOY_KEY: ${{ secrets.CONVEX_DEPLOY_KEY }}
        run: pnpm --filter @astrotan/backend exec convex deploy

      - name: Log in to GHCR
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Compute the lowercase image prefix
        id: img
        # GHCR n'accepte que des noms de dépôt en minuscules, alors que le
        # propriétaire GitHub peut contenir des majuscules.
        run: echo "prefix=ghcr.io/$(echo '${{ github.repository_owner }}' | tr '[:upper:]' '[:lower:]')" >> "$GITHUB_OUTPUT"

      - uses: docker/setup-buildx-action@v3

      - name: Build and push the web image
        uses: docker/build-push-action@v6
        with:
          context: .
          file: docker/web.Dockerfile
          push: true
          build-args: |
            PUBLIC_CONVEX_URL=${{ secrets.PUBLIC_CONVEX_URL }}
          tags: |
            ${{ steps.img.outputs.prefix }}/astrotan-web:${{ github.sha }}
            ${{ steps.img.outputs.prefix }}/astrotan-web:latest
          cache-from: type=gha
          cache-to: type=gha,mode=max

      - name: Build and push the admin image
        uses: docker/build-push-action@v6
        with:
          context: .
          file: docker/admin.Dockerfile
          push: true
          build-args: |
            VITE_CONVEX_URL=${{ secrets.VITE_CONVEX_URL }}
            VITE_CONVEX_SITE_URL=${{ secrets.VITE_CONVEX_SITE_URL }}
            VITE_WEB_SITE_URL=${{ secrets.VITE_WEB_SITE_URL }}
          tags: |
            ${{ steps.img.outputs.prefix }}/astrotan-admin:${{ github.sha }}
            ${{ steps.img.outputs.prefix }}/astrotan-admin:latest
          cache-from: type=gha
          cache-to: type=gha,mode=max

      # La configuration qui tourne sur le VPS vient du dépôt, à chaque
      # déploiement — sinon un compose édité à la main sur la machine
      # diverge en silence, et le rollback ne reproduit plus rien.
      - name: Configure the SSH client
        run: |
          install -m 700 -d ~/.ssh
          printf '%s\n' "${{ secrets.VPS_SSH_KEY }}" > ~/.ssh/id_deploy
          chmod 600 ~/.ssh/id_deploy
          printf '%s\n' "${{ secrets.VPS_SSH_KNOWN_HOSTS }}" > ~/.ssh/known_hosts
          chmod 600 ~/.ssh/known_hosts

      - name: Ship the compose stack
        run: |
          rsync -az --delete \
            -e "ssh -i ~/.ssh/id_deploy" \
            --exclude '.env' \
            docker/ "${{ secrets.VPS_USER }}@${{ secrets.VPS_HOST }}:~/astrotan/"

      # ÉTAPE 3 DU PIPELINE — `IMAGE_TAG` est le sha, jamais `latest` : ce
      # qui tourne sur le VPS doit être nommable pour être reproductible.
      - name: Pull and restart
        run: |
```

### Task 9: Rollback

**Files:**
- Create: `.github/workflows/rollback.yml`

**Interfaces:**
- Consomme : les images taguées par sha (Task 8)
- Produit : `workflow_dispatch` prenant un sha, rejouant le pipeline complet

- [ ] **Step 1: Écrire le workflow**

```yaml
# .github/workflows/rollback.yml
name: Rollback

# Jamais automatique : un rollback est une décision. `workflow_dispatch`
# avec un sha explicite — celui affiché dans le résumé du déploiement à
# rejouer, ou `cat ~/astrotan/DEPLOYED_SHA` sur le VPS.
on:
  workflow_dispatch:
    inputs:
      sha:
        description: "Commit sha complet à redéployer (40 caractères)"
        required: true
        type: string

concurrency:
  group: deploy
  cancel-in-progress: false

jobs:
  rollback:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: read
    steps:
      - uses: actions/checkout@v4
        with:
          # L'arbre du sha visé, functions Convex comprises : c'est tout
          # l'objet de ce workflow.
          ref: ${{ inputs.sha }}

      - name: Refuser un sha mal formé
        run: |
          echo "${{ inputs.sha }}" | grep -Eq '^[0-9a-f]{40}$' \
            || (echo "sha must be a full 40-character commit sha" && exit 1)

      - uses: actions/setup-node@v4
        with:
          node-version: "22"

      - name: Enable Corepack
        run: corepack enable

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      # LE POINT ENTIER DE CE WORKFLOW (spec §7). Repointer le compose sur
      # un tag d'image antérieur laisserait un frontend ancien face aux
      # functions Convex actuelles. La discipline expand/migrate/contract
      # rend ce redéploiement des anciennes functions sûr d'un cran en
      # arrière — et c'est exactement d'un cran qu'il s'agit.
      - name: Redeploy the Convex functions of that sha
        env:
          CONVEX_DEPLOY_KEY: ${{ secrets.CONVEX_DEPLOY_KEY }}
        run: pnpm --filter @astrotan/backend exec convex deploy

      - name: Log in to GHCR
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Compute the lowercase image prefix
        id: img
        run: echo "prefix=ghcr.io/$(echo '${{ github.repository_owner }}' | tr '[:upper:]' '[:lower:]')" >> "$GITHUB_OUTPUT"

      # Échouer ici plutôt que sur le VPS, à mi-chemin d'un `compose up`
      # dont un service ne démarrera jamais.
      - name: Vérifier que les deux images de ce sha existent
        run: |
          docker manifest inspect ${{ steps.img.outputs.prefix }}/astrotan-web:${{ inputs.sha }} >/dev/null
          docker manifest inspect ${{ steps.img.outputs.prefix }}/astrotan-admin:${{ inputs.sha }} >/dev/null

      - name: Configure the SSH client
        run: |
          install -m 700 -d ~/.ssh
          printf '%s\n' "${{ secrets.VPS_SSH_KEY }}" > ~/.ssh/id_deploy
          chmod 600 ~/.ssh/id_deploy
          printf '%s\n' "${{ secrets.VPS_SSH_KNOWN_HOSTS }}" > ~/.ssh/known_hosts
          chmod 600 ~/.ssh/known_hosts

      - name: Ship the compose stack of that sha
        run: |
          rsync -az --delete \
            -e "ssh -i ~/.ssh/id_deploy" \
            --exclude '.env' \
            docker/ "${{ secrets.VPS_USER }}@${{ secrets.VPS_HOST }}:~/astrotan/"

      - name: Pull and restart at that sha
        run: |
          ssh -i ~/.ssh/id_deploy "${{ secrets.VPS_USER }}@${{ secrets.VPS_HOST }}" \
            "cd ~/astrotan \
             && IMAGE_TAG=${{ inputs.sha }} GHCR_OWNER=$(echo '${{ github.repository_owner }}' | tr '[:upper:]' '[:lower:]') docker compose pull \
             && IMAGE_TAG=${{ inputs.sha }} GHCR_OWNER=$(echo '${{ github.repository_owner }}' | tr '[:upper:]' '[:lower:]') docker compose up -d \
             && echo ${{ inputs.sha }} > ~/astrotan/DEPLOYED_SHA"

      - name: Record the rollback
        run: echo "Rolled back to \`${{ inputs.sha }}\` — Convex functions redeployed from that tree, images repinned." >> "$GITHUB_STEP_SUMMARY"
```

