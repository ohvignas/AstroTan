# Lot 1 — Socle : Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Monorepo opérationnel avec un backend Convex authentifié par Better Auth, trois rôles appliqués côté serveur, et un dashboard où l'on se connecte et invite des utilisateurs.

**Architecture:** pnpm workspaces + Turborepo. `packages/backend` héberge Convex et, en Local Install, les tables Better Auth générées — l'utilisateur Better Auth porte le rôle, source unique de vérité. Chaque mutation revérifie les permissions ; l'invariant « owner unique » vit dans `databaseHooks` parce que c'est le seul point que les endpoints du plugin `admin()` traversent aussi.

**Tech Stack:** pnpm · Turborepo · TypeScript · Convex · Better Auth (`@convex-dev/better-auth` Local Install) · TanStack Start · React 19 · Tailwind v4 · shadcn/ui · Vitest + convex-test (`edge-runtime`)

**Spec:** `docs/superpowers/specs/2026-08-27-astrotan-design.md`

## Global Constraints

- **Versions figées** (spike du 2026-08-27, spec §9). `better-auth@1.6.17` et `@convex-dev/better-auth@0.12.5` en **exact, sans `^` ni `~`** : à partir de 1.6.18 le typage de `ConvexBetterAuthProvider` casse. Ne pas suivre le `~1.6.15` de la doc officielle, qui résout en 1.6.30 et produit une base cassée.
- **`convex-helpers` en dépendance directe** de `packages/backend`. C'est une transitive de `@convex-dev/better-auth` ; pnpm strict ne la hisse pas, et son absence casse la génération de schéma avec un `MODULE_NOT_FOUND` opaque.
- **La CLI Better Auth est le paquet npm `auth`**, pas `@better-auth/cli` (qui suit une autre ligne de versions, arrêtée à 1.4.21). Toujours l'appeler dans la version de `better-auth` : `pnpm dlx auth@1.6.17 generate --y`.
- **Node 22.** Le VPS et la CI tournent sur `node:22-alpine`.
- **Aucune API de cette stack écrite de mémoire.** Astro 7, TanStack Start 1 et `@convex-dev/better-auth` bougent vite. Consulter le MCP correspondant (`astro-docs`, `convex-docs`, `better-auth`, `shadcn`) avant d'écrire du code qui les touche.
- **Le rôle se lit sur l'utilisateur Better Auth.** Aucune table applicative ne contient de champ `role`. `profiles` n'en a pas.
- **`betterAuth/schema.ts` est généré.** Ne jamais l'éditer à la main : changer la config Better Auth, puis régénérer.
- **Toute mutation et toute query non publique commence par `requireRole`.** L'UI masque, elle ne décide pas.
- **TDD strict :** test qui échoue → vérifier qu'il échoue → implémentation minimale → test qui passe → commit.
- **Commits en anglais, Conventional Commits.** Le reste des échanges en français.

```ts
// packages/backend/convex/lib/authz.ts
import { ConvexError } from "convex/values"
import { authComponent } from "../auth"
import type { Role } from "../validators"


const ROLES: readonly Role[] = ["owner", "admin", "editor"]

// `role` arrive en `string | null | undefined` : le schéma Better Auth ne le
// contraint pas. On valide explicitement plutôt que de caster.
function parseRole(raw: unknown): Role | null {
  return typeof raw === "string" && (ROLES as readonly string[]).includes(raw)
    ? (raw as Role)
    : null
}

export async function requireRole(ctx: any, roles: Role[]) {
  const authUser = await authComponent.getAuthUser(ctx)
  if (!authUser) throw new ConvexError({ code: "UNAUTHENTICATED" })
  const role = parseRole(authUser.role)
  // null couvre trois cas : rôle absent, null, ou valeur inconnue ("superadmin").
  // Tous échouent fermé.
  if (!role || !roles.includes(role)) throw new ConvexError({ code: "FORBIDDEN" })
  return { ...authUser, role }
}

// Un editor n'écrit que ses propres documents. requireRole ne suffit pas.
export function requireOwnDocument(
  authUser: { _id: string; role: string },
  doc: { createdBy: string },
) {
  if (authUser.role === "editor" && doc.createdBy !== authUser._id) {
    throw new ConvexError({ code: "FORBIDDEN" })
  }
}
```

```ts
test("toute mutation exportée est déclarée dans le registre", async () => {
  const modules = import.meta.glob("../*.ts", { eager: true })
  const declared = new Set(MUTATION_REGISTRY.map((e) => e.name))
  const missing: string[] = []
  for (const [path, mod] of Object.entries(modules)) {
    const file = path.replace(/^\.\.\//, "").replace(/\.ts$/, "")
    if (file.startsWith("_") || file === "schema") continue
    for (const [name, fn] of Object.entries(mod as Record<string, any>)) {
      if (fn?.isMutation && !declared.has(`${file}.${name}`)) missing.push(`${file}.${name}`)
    }
  }
  expect(missing).toEqual([])
})
```

C'est ce test qui rend la matrice honnête : sans lui, oublier une entrée du registre
supprime silencieusement la couverture au lieu de la signaler.

```ts
// packages/backend/convex/lib/ownerGuard.ts
import type { Role } from "../validators"

export type OwnerInvariantInput = {
  actorId: string
  actorRole: Role
  targetId: string
  targetRole: Role
  nextRole: Role | null // null = suppression
  ownerCount: number
}

export class OwnerInvariantError extends Error {}

export function assertOwnerInvariant(i: OwnerInvariantInput): void {
  if (i.targetRole === "owner" && i.actorId !== i.targetId) {
    throw new OwnerInvariantError("FORBIDDEN: seul un owner peut se modifier lui-même")
  }
  if (i.nextRole === "owner" && i.targetRole !== "owner") {
    throw new OwnerInvariantError("OWNER_ALREADY_EXISTS: un seul owner est autorisé")
  }
  if (i.targetRole === "owner" && i.nextRole !== "owner" && i.ownerCount <= 1) {
    throw new OwnerInvariantError("LAST_OWNER: le dernier owner ne peut être ni rétrogradé ni supprimé")
  }
}
```

Logique pure et sans dépendance Convex : elle se teste exhaustivement, et les hooks
n'ont plus qu'à la câbler.

```ts
// packages/backend/convex/lib/token.ts
const hex = (bytes: Uint8Array) =>
  [...bytes].map((b) => b.toString(16).padStart(2, "0")).join("")

export async function hashToken(token: string): Promise<string> {
  const digest = await crypto.subtle.digest("SHA-256", new TextEncoder().encode(token))
  return hex(new Uint8Array(digest))
}

export async function generateToken(): Promise<{ token: string; hash: string }> {
  const bytes = new Uint8Array(32)
  crypto.getRandomValues(bytes)
  const token = hex(bytes)
  return { token, hash: await hashToken(token) }
}
```

`crypto.subtle.digest` est asynchrone, donc `generateToken` l'est aussi. Les deux
sont disponibles dans l'environnement `edge-runtime` de Vitest comme dans le runtime
Convex : pas de dépendance à `node:crypto`.

```ts
// packages/backend/convex/invitations.ts
import { v } from "convex/values"
import { ConvexError } from "convex/values"
import { mutation } from "./_generated/server"
import { requireRole } from "./lib/authz"
import { generateToken, hashToken } from "./lib/token"
import { roleValidator } from "./validators"

const SEVEN_DAYS = 7 * 24 * 60 * 60 * 1000

export const create = mutation({
  args: { email: v.string(), role: roleValidator },
  handler: async (ctx, args) => {
    const actor = await requireRole(ctx, ["owner", "admin"])
    // Un admin ne fabrique pas un owner : l'invariant owner unique se contournerait
    // par l'invitation si on ne bloquait pas ici.
    if (args.role === "owner") throw new ConvexError({ code: "FORBIDDEN" })
    const { token, hash } = await generateToken()
    await ctx.db.insert("invitations", {
      email: args.email,
      role: args.role,
      tokenHash: hash,
      expiresAt: Date.now() + SEVEN_DAYS,
      invitedBy: actor._id,
    })
    return { token } // renvoyé une seule fois, pour l'email ; jamais relisible ensuite
  },
})

export const accept = mutation({
  args: { token: v.string(), password: v.string() },
  handler: async (ctx, args) => {
    const hash = await hashToken(args.token)
    const invite = await ctx.db
      .query("invitations")
      .withIndex("by_token_hash", (q) => q.eq("tokenHash", hash))
      .unique()
    if (!invite) throw new ConvexError({ code: "INVALID" })
    if (invite.acceptedAt) throw new ConvexError({ code: "ALREADY_ACCEPTED" })
    if (invite.expiresAt < Date.now()) throw new ConvexError({ code: "EXPIRED" })
    // Création du compte Better Auth avec le rôle porté par l'invitation.
    // Vérifier la signature exacte via le MCP `better-auth` avant d'écrire.
    await ctx.db.patch(invite._id, { acceptedAt: Date.now() })
    return { email: invite.email, role: invite.role }
  },
})
```

L'ordre des trois refus compte : `ALREADY_ACCEPTED` est testé avant `EXPIRED`, sinon
une invitation consommée puis expirée renverrait le mauvais code d'erreur et le test
d'idempotence deviendrait instable.
